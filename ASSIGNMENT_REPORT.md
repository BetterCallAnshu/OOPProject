<p class=MsoNormal style='margin-bottom:12.0pt'><span style='mso-fareast-font-family:
"Times New Roman"'>--- ## 1. Introduction Duplicate files are two or more files
on a computer that contain the exact same data. They are not the same as two
files that happen to have the same name — duplicate files have identical
content, even if they are in different folders or have different names. Duplicate
files are created very often during normal use of a computer. A student may
copy the same assignment into several folders, a backup tool may create copies
of the same file, or a download may save the same document in more than one
place. Over time, these copies take up a lot of extra space on the hard drive,
and they also make it harder to find the right version of a file. The Duplicate
File Detection System is a Java program that scans a folder (or a whole drive),
reads every file, and finds groups of files that have the same content. It then
prints the results on the screen and also writes them into a text report file.
This helps a user see which files are duplicates so they can delete the extra
copies and free up disk space. --- ## 2. Objectives The main objectives of this
project are: 1. To understand how Java can read files from a folder and all its
subfolders. 2. To learn how to use hashing to compare the content of two files.
3. To use Java collections such as HashMap, ArrayList and List to store and
group data. 4. To build a working program that solves a real, everyday problem
— finding duplicate files. 5. To practice exception handling so that the
program keeps working even when it runs into locked or inaccessible files. ---
## 3. Concepts Used The following Java concepts were used in this project: ###
3.1 File Handling File handling in Java means reading from and writing to files
on the disk. In this project, file handling is used in three places: - Reading
a file's size and checking whether it is a regular file. - Reading the content
of a file so that it can be hashed. - Writing the final report into a text file
on the disk. The program uses the `java.nio.file` package, which is the modern
way to work with files in Java. It uses `Path` to represent a file location and
`Files` to perform operations like checking if something is a directory,
reading file sizes, walking through folders, and writing the report. ### 3.2
Hashing A hash is a fixed-size string that is produced from the content of a
file using a mathematical function. If two files have the same content, they
will always produce the same hash. If they have different content, their hashes
will be different. In this project, SHA-256 hashing is used. SHA-256 produces a
64-character hexadecimal string (for example, `a3f2b1c9...`). This hash acts
like a digital fingerprint of the file. Instead of reading and comparing the
full content of every file against every other file, the program hashes each
file and compares the short hash values. The hashing is done using the
`java.security.MessageDigest` class with the algorithm name
`&quot;SHA-256&quot;`. ### 3.3 Collections Collections are used to store and
group the file data while the program runs: - **HashMap** — A HashMap stores
data as key-value pairs. In this project, one HashMap is used to group files by
their size (`Map<Long, List><Path>&gt;`). Another HashMap is used to group
files by their content hash (`Map<String, List><FileMetadata>&gt;`). Using a
HashMap makes it very fast to look up files by size or by hash. - **ArrayList /
List** — An ArrayList is used to hold the list of file paths for a given
size, and also to hold the list of duplicate files for a given hash. `List` is
used in the method signatures so the code is clean and easy to read. Using
HashMap in particular is important because it makes the search very fast.
Instead of comparing every file with every other file (which would be very
slow), the program uses HashMap to instantly find only the files that could
possibly be duplicates. --- ## 4. Working / Algorithm The program follows a
simple step-by-step process. It does not hash every file right away, because
hashing means reading the complete content of a file, which takes time.
Instead, it uses a two-step approach: ### Step 1: Walk through the folder The
program starts at the folder given by the user. It walks through that folder
and all the subfolders inside it. For every regular file it finds, it gets the
file size in bytes. If a file is locked or cannot be opened, the program prints
a warning and skips it, but it keeps going. This is done using
`Files.walkFileTree` with a `SimpleFileVisitor`. ### Step 2: Group files by
size All the files found in step 1 are put into a HashMap where the key is the
file size and the value is a list of files with that size. Files that have a
size that no other file shares cannot possibly be duplicates, so they are
ignored in the next step. ### Step 3: Hash the candidates For every size that
has two or more files, the program reads each file completely and computes its
SHA-256 hash. Each file is then stored in a second HashMap where the key is
`size:hash` and the value is a list of files that share that size and hash. ###
Step 4: Find the duplicate groups After all the candidate files are hashed, the
program looks at the second HashMap. Any group that contains more than one file
is a group of duplicate files. These groups are sorted by file path and
returned as a list of lists. ### Step 5: Print and save the report The
duplicate groups are shown on the screen, one group at a time. For each group,
the program shows how many copies there are, the size of each copy, and the
full path of each file. It also calculates how much space could be saved by
deleting all but one copy. Finally, the same report is written to a text file.
### Flowchart (Mermaid) ```mermaid flowchart TD A[Start: get folder path from
user] --&gt; B{Is it a valid folder?} B -- No --&gt; Z[Print error, exit] B --
Yes --&gt; C[Walk folder tree and get size of every file] C --&gt; D[Group
files by size using HashMap] D --&gt; E{Size has 2 or more files?} E -- No
--&gt; F[Ignore: cannot be duplicate] E -- Yes --&gt; G[Read each file and
compute SHA-256 hash] G --&gt; H[Group hashed files by size:hash using HashMap]
H --&gt; I{Group has more than 1 file?} I -- No --&gt; F I -- Yes --&gt; J[Add
group to duplicate list] J --&gt; K[Repeat for all sizes] K --&gt; L[Sort
groups and files by path] L --&gt; M[Print report on screen] M --&gt; N[Write
report to text file] N --&gt; O[End] ``` --- ## 5. Implementation The project

### 5.2 FileHasher.java This class is responsible for hashing a file's content.
When it is created, it gets a SHA-256 `MessageDigest` object. When `hash()` is
called with a file path, it: 1. Resets the digest. 2. Opens the file using
`Files.newInputStream(file)`. 3. Reads the file in small chunks of 8192 bytes
using a `byte[]` buffer inside a `while` loop. 4. Feeds each chunk to the
digest with `digest.update()`. 5. Converts the final digest bytes into a
lowercase hex string using `toHex()`. ```java public String hash(Path file)

return toHex(digest.digest()); } private static String toHex(byte[] bytes) {
StringBuilder sb = new StringBuilder(bytes.length * 2); for (byte b : bytes) {
sb.append(Character.forDigit((b &gt;&gt; 4) &amp; 0xF, 16));
sb.append(Character.forDigit(b &amp; 0xF, 16)); } return sb.toString(); } ```
**What it does:** It turns the content of a file into a 64-character hash
string. Two files with the same hash are treated as having the same content.

Advantages 1. **Saves disk space.** It finds duplicate files so that extra
copies can be deleted. 2. **Uses hashing, not just names.** Two files with
different names but the same content are correctly identified as duplicates. 3.
**Fast on large folders.** The program groups files by size first, so it only
reads the full content of files that might actually be duplicates. 4. **Works
on any folder.** The user can give any folder path, and the program will scan
it and all its subfolders. 5. **Keeps going on errors.** If some files or
folders cannot be opened, the program shows a warning and continues instead of
stopping completely. 6. **Gives a saved report.** The results are written to a
text file, so the user has a copy to look at later. ### Limitations 1.
**SHA-256 is slower than a simple name or size check.** Reading and hashing the
full content of a file takes time. This is necessary for correctness, but it
means large files take longer to scan. 2. **Cannot tell if files are
intentionally different.** For example, two files may have the same size and
even the same hash but could be different in some edge case. SHA-256 collisions
are extremely unlikely in normal use, so this is not a big concern. 3. **Empty
files.** All zero-byte files will be grouped together as duplicates, even if
they are in different places for different reasons. 4. **Cannot fix the problem
automatically.** The program only finds duplicates. It does not delete or move
files by itself, so the user still has to decide what to do. 5. **Scans one
folder tree at a time.** If the user wants to scan several separate folders,
they would need to run the program again for each one. 6. **Only works on files
the user has permission to open.** Locked system folders cannot be checked, so
some files may be skipped. --- ## 8. Future Scope Some things that could be
added to this project in the future are: 1. **Delete or move duplicates.** The
program could be extended to let the user choose which copy to keep and then
delete or move the extra copies safely. 2. **Add a graphical user interface.**

by date or name as well.** The program could show extra details like file
creation date, last modified date, and file name to help the user decide which
copy to keep. --- ## 9. Conclusion The Duplicate File Detection System is a
